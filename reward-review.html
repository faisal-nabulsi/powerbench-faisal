Real learning — not reward hacking

Held-out reward +43%, while the model wrote 57% less code.

A model gaming a reward inflates its output. This one did the opposite: it got substantially better at slide layout while more than halving its response length. The gain is concentrated in collision — it learned to stop putting images on top of text — which is exactly the defect class found by hand-auditing its slides.

See it — the model's own slides

Early in training

Overlapping text boxes and images stacked on copy. The grader scores these 0.34–0.39 and, crucially, a human agrees they are bad — that alignment is what makes the reward trustworthy.

After training

Clean separation, content on-canvas, text inside its box — and produced with roughly half the code. Same grader, same task family, same model.

This is the check that matters most. A reward is only trustworthy if a high score looks good to a person. Reviewing these renders by eye is what surfaced five separate grader bugs — including a background photo being counted as an "overlap", which was actively teaching the model to avoid background images.

Four things had to be true at once: a grader that detects defects; a task with headroom (detailed prompts let the model transcribe a spec — too easy); a learning rate in the usable band (1e-6 too low, 3e-6 degenerates); and a response-length cap that bites, which is what forced the model out of its verbosity spiral.

The reward — 7 deterministic checks, no LLM judge

metricweightwhat it measures
collision0.22per-shape overlap; covering text is penalised steeply (unreadable)
overflow0.20per-shape area outside the canvas, with a 2% safe margin
textfit0.16estimated rendered text height vs its box
density0.16content in a healthy band — punishes empty and crammed
contrast0.10WCAG luminance ratio — catches invisible text
imbalance0.10area-weighted centroid offset from centre
aspect0.0616:9 compliance (now solved via the prompt)

Invalid output scores 0.0, never negative. A negative floor makes every rollout in a GRPO group identical — zero relative advantage, therefore zero gradient. That single mistake collapsed the first run.

Hand-audit → grader fix → model improvement

Reviewing rendered slides by eye found five grader bugs no unit test would have caught.

bug found by eyefix
Image sitting on text scored 0.96defects were divided by total slide area → now measured per-shape
64pt text in a 144pt box "fit"text-fit only read run-level fonts → now reads paragraph-level too
Content fully off-screen still scored 0.65one catastrophe was averaged away by five good metrics → soft-min gate
24 of 30 slides were 4:3, unpenalisedadded aspect metric; then moved 16:9 into the prompt
Background photo counted as "overlap"full-bleed shapes now treated as backgrounds — this was teaching the model to avoid background images
Slide rendered blank but scored 0.83invisible (white-on-white) text → new contrast metric scores it 0.00

The rule this produced: measure a metric's variance across real rollouts before giving it weight. GRPO learns only from differences within a group — a constant metric contributes zero gradient while diluting the ones that teach. Aspect ratio failed that test (every rollout was 4:3); contrast passed it (sd 0.36).

Honest limits. The held-out eval is 45 tasks × 1 sample (SE ≈ 0.045) — ample for this +0.21 effect, too weak for the +2–3% originally targeted. The reward measures layout, not whether the content is correct or the deck is beautiful; "just looks ugly" is not captured (an alignment metric is built and gate-tested but was not active in this run). Results are on our grader, not the published SlidesBench metric — the public release ships instructions without reference decks, so an official comparable number would require those. Single-turn generation, not the agentic render-inspect-fix loop (built, idle). Density and balance drifted slightly down, plausibly from much shorter output — worth watching.
