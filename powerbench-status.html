What it took (the honest version)

This was not push-button. Getting the full loop running meant working through a real gauntlet on a bleeding-edge stack (a July-2026 model architecture on a July-2026 torch/CUDA): a terminated box and full rebuild, a missing build tool, verl defaulting to an attention backend we don't have (fixed with a clean config override), a multimodal dataset that filtered itself empty, and a flash-attn library that won't compile against CUDA 13 — solved by dropping in the one pure-Python helper verl actually needs. Every fix and the exact working config is documented, and the environment rebuilds from a single script if the box dies again.

Where it stands right now

The hill-climb is executing: verl scores the 45 eval tasks to get a baseline, runs GRPO on the 141 training tasks with the SlidesBench reward, then re-scores the eval set. The before → after delta on that eval set is the proof-of-life (+2–3% is the bar). Baseline number lands shortly; the full run completes within the next few hours.

Honest caveat on the reward: the public SlidesBench repo ships instructions only, no reference decks, so the exact reference-based metric can't run yet. The proof-of-life uses a program-scored proxy (execute the generated code → score text-coverage + execution + layout). It's deterministic and real, but somewhat gameable — it proves the training loop moves a program-computed number, which is the Phase-2 question. The honest reference-based metric and Cara's grader plug into the exact same slot once we have reference decks / the powerbench env.
